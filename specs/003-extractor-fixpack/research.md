## R31. The collision is a foreign file, declared once per test project (Verified)

**Decision**: rule 1 targets the SDK-injected program file by *where it lives*, not by what it is.

**Evidence**: the current extractor, run 2026-09-13 against `MemOS.sln` into a scratch map:


The scratch map file was left at 0 bytes (002 FR-106: a refused first run rolls creation back). The file:

```vb

Namespace Global
Module __MicrosoftTestPlatformAutoGeneratedProgram
<Microsoft.VisualStudio.TestPlatform.TestSDKAutoGeneratedCode>
```

It is compiled into every project that references `Microsoft.NET.Test.Sdk` (MemOS has two: `MemOS.ContractTests`
and `MemOS.IntegrationTests`, both at 17.8.0). Its module sits in the global namespace, so root namespaces do
not separate the two copies. The live map already holds it twice: GameRoom and CodeMem each carry the rows
`T:__MicrosoftTestPlatformAutoGeneratedProgram` (module) and `M:__MicrosoftTestPlatformAutoGeneratedProgram.Main(System.String[])`
at `../../../.nuget/packages/microsoft.net.test.sdk/<version>/build/net8.0/Microsoft.NET.Test.Sdk.Program.vb`,
and 6 edges in the map carry a `../` path (the `part_of` edges of those rows and the like).

**MemOS in-repo collision candidates, scanned 2026-09-13**: the ten project root namespaces are all distinct
(`MemOS.Core`, `.Data`, `.Business`, `.Shell`, `.Abstractions`, `.Mcp`, `.Modules.DbToolkit`, `.Modules.Mcp`,
`.ContractTests`, `.IntegrationTests`), so the VB `My` types the task warns about (`My.MyApplication`,
`My.Resources`, `My.MySettings`) cannot share an id; they are compiler-embedded trees in any case, not
documents, and are never rows. Files linked across the two test projects (`ElcxFixtures.vb` into the contract
project; `SyntheticElcxBuilder.vb`, `CodeMemMapFixture.vb`, `CodeMemSymbolScenario.vb`, `CodeMemOrphanScenario.vb`

No `Namespace Global` block exists in MemOS source. **Prediction**: after rule 1 MemOS completes. The
prediction is not the acceptance; the run is.

## R32. A compile-item test cannot express the rule (Verified)

**Decision**: the predicate is a path prefix, not "not among the project's compile items".

**Evidence**: the injected file *is* a compile item — the SDK's targets add it to the evaluated `Compile` list,
and `Project.Documents` (what `CompiledInputs` enumerates and what the symbol walker's allowed-tree set is built
from) contains it; that is how it reached `code_symbols` with a `../../../.nuget/…` path in the first place.
Every other distinguishing property (its `<auto-generated>` comment, its attribute, its `Global` namespace)
is a property of this one file and not a rule. The path is the only compiler-visible fact that separates
"the solution's code" from "what the build injected".

## R33. The scope root is what `solutions.repo_root` already records (Decided)

**Decision**: `GitFacts.RepoRoot` (LibGit2Sharp's `Repository.Info.WorkingDirectory`, read once per run by
`GitProvenance.Read`, written unchanged to `solutions.repo_root`) when non-null; otherwise
`SolutionPaths.BaseDirectory(solutionPath)`. Resolved once, after step 7's provenance read and before step 8's
staging, by a new `SolutionScope` type whose `Contains(fullPath)` is the one door (Article XII).

**Prefix rule** (as ruled at STOP 1): both sides through `Path.GetFullPath` (relative segments resolved),
alternate separators replaced by the platform separator, the root given one trailing separator if absent;
`StartsWith(…, StringComparison.OrdinalIgnoreCase)` — the comparison the existing `obj/` exclusion in
`CompiledInputs.IsSourceDocument` uses. Consequence: `C:\repo2\` is not under `C:\repo\`. The Red for the
injected file reaches it through a relative include with `..` segments, the form the 2026-09-12 refusal
printed, and the recorded Red line shows that form.

**Alternatives considered**:
- *No scoping without a repository*: leaves a non-repository solution with two test projects unmappable, and
  makes the rule untestable on the fixture (which is not a repository) without creating repositories in every
  test. Rejected; the fallback is the solution directory, the tree the Operator pointed at.
- *Discover the repository even without a commit* (`Repository.Discover` alone): would diverge from
  `solutions.repo_root`, which Stage A writes only when HEAD has a tip. Rejected: one value, one door; the
  no-commit case is an edge case in the spec, not a second rule.
- *A literal `.nuget/packages/` path rule*: a second door for the same decision, and wrong for a
  repository-local cache. Rejected; recorded in the spec's Edge Cases.

## R34. How bare names bind (Verified with a probe, 2026-09-13)

A scratch console (Roslyn 4.14.0, `Option Strict On`, root namespace `Sample`, global imports
`Microsoft.VisualBasic` and `System`) parsed a class exercising every shape and printed
`GetSymbolInfo(simpleName)` and `GetEnclosingSymbol(position)` for each `SimpleNameSyntax`:

| Shape in source | Parent node kind | Bound symbol | Note |
|-----------------|------------------|--------------|------|
| `Max * 2` in a field initializer | `MultiplyExpression` | Field (Const) | enclosing = the initialised field |
| `Return _count` in a getter | `ReturnStatement` | Field | enclosing = `get_Count` (accessor → property via `AssociatedSymbol`) |
| `_count = value` in a setter | `SimpleAssignmentStatement` | Field / Parameter | the parameter is skipped by kind |
| `Optional limit As Integer = Max` | `EqualsValue` | Field | enclosing = the parameter → containing method |
| `_count += 1` | `AddAssignmentStatement` | Field | one identifier, one occurrence |
| `Count = _count + Max` | `SimpleAssignmentStatement`, `AddExpression` | Property, Field, Field | a set and two reads: three occurrences |
| `Refresh` (no parentheses) | **`InvocationExpression`** | Method (Ordinary) | **parsed as an invocation: already recorded by today's rule** |
| `Run(1)` (overloaded) | `InvocationExpression` | Method `Run(Integer)`, 0 candidates | the identifier binds to the resolved overload, same token as the invocation shape → dedup |
| `AddressOf OnChanged` | `AddressOfExpression` | Method (Ordinary) | the rule 2 case |
| `AddHandler Changed, …` / `RaiseEvent Changed(…)` / `RemoveHandler Changed, h` | the statement | Event | Q5 |
| `vbCrLf` | `ConcatenateExpression` | Field `Microsoft.VisualBasic.Constants.vbCrLf` | external → not a row → not written (Q4) |
| `NameOf(_count)` | `NameOfExpression` | Field | bound like any other use |
| `New Other With {.Label = s}` | `NamedFieldInitializer` | Property | a bare property set that no member-access node carries today |
| `arr(0)` where `arr` is a local | `InvocationExpression` | Local | skipped by kind; a field array binds to the field |
| `Foo(Of Integer)()` | `InvocationExpression` (a `GenericName`) | Method (constructed) | `DocIdOf` uses the original definition |
| `EventArgs.Empty` | `SimpleMemberAccessExpression` | NamedType / Field | the member name is the member-access shape, already recorded; the type name is skipped by kind |
| `<Serializable>` | `Attribute` | Method (**Constructor**) | skipped by kind and by parent |
| `GetType(T)` | `GetTypeExpression` | TypeParameter | skipped by kind |
| `As EventHandler`, `As Other`, `New Other` | `SimpleAsClause`, `ObjectCreationExpression` | NamedType | skipped by kind (and are `uses` / `calls` under their own rules) |

No candidate ambiguity arose in any row (`CandidateSymbols.Length = 0`, `CandidateReason.None`).

**Consequences for the rule** (FR-208): the kind filter (field, property, event, method of kind Ordinary /
DeclareMethod / ReducedExtension) does most of the work; the syntactic exclusions needed are exactly: the
`Name` of a member access, any child of a qualified name, the `Name` of an attribute, and the four other-verb
clauses `CallsRule.InsideOtherVerbClause` already checks. A parenthesis-less call needs no new handling.

## R35. Coincident occurrences fold in canonicalisation (Decided)

`ExtractionRun.Canonical` deduplicates on (source, verb, target, via, path, offset, length). For `Run(1)` the
invocation shape locates the edge at the `Run` identifier (`NameTokenOf(invocation.Expression)`), and the
bare-name shape locates it at the same token with the same source and target, so the two fold to one row.
The same holds for `Refresh` and for a parameterised property `Items(0)`. No new dedup logic; FR-213 is
satisfied by the existing key and is asserted by SC-204's exact counts.

## R36. Rows only (Decided — spec Q4)

`codemem_references` (058 FR-018) takes a mapped symbol id and returns occurrences whose *resolved target*
is that symbol; `codemem_orphans` (059 FR-010) counts inbound edges whose `target_symbol_id` is a row;
`codemem_symbol_detail` (058 FR-013/FR-015) lists a symbol's outbound edges grouped by verb, external targets
included. Only the third would show an external bare-name edge, and it would show one per `vbCrLf`, `vbTab`,
`Math.PI` reached through an `Imports`. The description's invariant ("non-NULL `target_symbol_id`") is met by
construction when the target must be a row. Recorded as the one asymmetry with member access.

## R38. Extractor version 0.2.0 (Decided — spec Q7)

`CodeMem.Extraction.vbproj` `<Version>` 0.1.0 → 0.2.0; `ExtractionRun.ExtractorVersion()` already stamps
Major.Minor.Build from the assembly. Article IV's determinism is defined per extractor version; without the
bump, GameRoom's next run has the same digest and the same version as run 2 with a different fact set.

## R39. Creating a repository in a test (Decided; verify at implementation)

`LibGit2Sharp` 0.32.0 is a package reference of `CodeMem.Extraction`; the test project references that
project, so the assembly flows transitively. The repository test uses `Repository.Init(copy.ParentDirectory)`,
`Commands.Stage(repo, "*")` and `repo.Commit(message, signature, signature)` so that HEAD has a tip and
`GitFacts.RepoRoot` is written. The copy's `bin/` and `obj/` are absent at copy time and the restore's outputs
are staged too; the dirty flag is not asserted in that test. If the transitive reference does not compile
(`Imports LibGit2Sharp` unresolved), add the same package at the same version to the test project — a pin,
not a new dependency.

## R40. Cost of the fourth shape (Decided; measure at implementation)

Every `SimpleNameSyntax` in every in-scope tree gets one `GetSymbolInfo` call; type names in `As` clauses are
among them and bind to types (skipped by kind). GameRoom's trees hold on the order of tens of thousands of
simple names; each binding is a cached-model lookup. SC-010's 60 s fixture budget is the gate; the acceptance
runner reports elapsed time on GameRoom. A syntactic pre-filter (skip names whose parent is a type position)
is available if the measurement demands it and is not designed in advance.
